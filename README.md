# NeAvito — этапы 1–7: основные API, личные кабинеты и публичный каталог

Реализованы POST /api/auth/register, POST /api/auth/login, POST /api/auth/logout и GET /api/auth/me.
Регистрация не выполняет автоматический вход. Вход создает защищенную HttpOnly cookie; используйте HTTPS.
Пользователь может покупать и продавать из одного аккаунта. Реализованы публичный каталог и личные кабинеты. Страницы корзины и оформления — следующие этапы.

## Подготовка

.NET 10 уже установлен. Установите Docker Desktop для Windows с официального сайта https://docs.docker.com/desktop/setup/install/windows-install/ и запустите его. Используйте Linux containers / WSL 2. Если установщик потребует WSL, выполните в PowerShell администратора `wsl --install`, перезагрузите компьютер и повторно запустите Docker Desktop.

В терминале из папки C:\Users\saren\source\repos\NeAvito:

```powershell
Copy-Item .env.example .env
```

Откройте .env и замените пароль своим локальным паролем. Затем:

```powershell
docker compose up -d postgres
dotnet tool restore
dotnet user-secrets init --project NeAvito
dotnet user-secrets set "ConnectionStrings:Postgres" "Host=localhost;Port=15432;Database=neavito;Username=neavito;Password=ВАШ_ПАРОЛЬ" --project NeAvito
dotnet ef database update --project NeAvito
dotnet dev-certs https --trust
dotnet run --project NeAvito --launch-profile https
```

Пароль должен совпадать с .env. User Secrets предназначен только для локальной разработки. Не добавляйте пароль в appsettings или исходный код.
Повторное изменение POSTGRES_PASSWORD не меняет пароль уже созданной базы: для существующей базы изменяйте пароль средствами PostgreSQL.

В Visual Studio откройте NeAvito.slnx, выберите NeAvito запускаемым проектом и профиль https.

## Этап 2: каталог и товары

Добавлены модели товара, категории и фотографии, а также миграция AddCatalog. После обновления проекта остановите запущенное приложение и выполните:

```powershell
dotnet ef database update --project NeAvito
dotnet run --project NeAvito --launch-profile https
```

Дополнительные установки и NuGet-пакеты для этого этапа не нужны.

- GET /api/catalog/categories — шесть начальных категорий.
- GET /api/catalog/products — опубликованные товары, включая товары без остатка с isAvailable=false.
- GET /api/catalog/products/{id} — карточка опубликованного товара. Для скрытого или отсутствующего товара возвращается 404.

Параметры каталога: search (название, без учета регистра), categoryId, minPrice, maxPrice (рубли), sort (newest, oldest, price_asc, price_desc), page (от 1), pageSize (1–100, по умолчанию 20).
Ответ содержит items, page, pageSize, totalCount, totalPages. При одинаковом значении сортировки используется идентификатор товара, чтобы порядок был стабильным.
Цены хранятся целым количеством копеек, API возвращает рубли и currency=RUB. Поддерживаемый диапазон цены товара — больше нуля, до 1 млрд рублей.

Каталог после миграции пуст: демонстрационные товары не добавляются в пользовательскую базу. Создание товаров продавцом и загрузка изображений реализованы на этапе 3, описанном ниже. Интерфейс личного кабинета реализован на этапе 6. Публичный каталог и карточка реализованы на этапе 7. Страницы корзины и оформления покупки еще предстоит добавить.


## Этап 3: управление товарами продавцом

Любой зарегистрированный пользователь может быть продавцом. Все операции /api/seller/products требуют входа и работают только с собственными товарами. Для чужого или отсутствующего товара возвращается 404.

- POST /api/seller/products — создать черновик (name, description, price в рублях, stock, categoryId).
- GET /api/seller/products?page=1&pageSize=20 — собственные товары со всеми статусами.
- GET /api/seller/products/{id} — собственная карточка, включая version.
- PUT /api/seller/products/{id} — изменить данные, передав поля создания и актуальную version.
- POST /api/seller/products/{id}/publish — опубликовать.
- POST /api/seller/products/{id}/unpublish — снять с публикации без удаления записи.
- POST /api/seller/products/{id}/images — загрузить один файл через multipart/form-data, имя поля file.
- DELETE /api/seller/products/{id}/images/{imageId} — удалить фотографию.

Нулевая цена и отрицательный остаток запрещены. Цена содержит не больше двух знаков после запятой. Существование категории проверяется. Товар с нулевым остатком можно опубликовать, но каталог показывает isAvailable=false. Название и описание обязательны.

После изменения товара, статуса или фотографий версия обновляется. При редактировании со старой версией возвращается 409: получите карточку заново перед повторной отправкой.

### Фотографии

До 10 фотографий на товар. JPEG, PNG и WebP, до 5 МБ на файл, до 12 мегапикселей и до 6000 пикселей по стороне. Поврежденные и анимированные файлы отклоняются. Файл декодируется и заново кодируется в WebP, исходное имя не используется при сохранении.

Файлы хранятся в NeAvito/App_Data/product-images. Эта папка исключена из Git и должна попадать в резервную копию вместе с базой. При развертывании в контейнере ей потребуется постоянный том. Путь можно переопределить настройкой Images:StoragePath (абсолютный путь).

URL фотографии возвращается после загрузки. Фотографии опубликованных товаров доступны всем, скрытых — только владельцу. Для загрузки используйте Postman или другой клиент с поддержкой multipart и сохранением cookie: сначала выполните вход по HTTPS, затем выберите Body → form-data → file (тип File) и прикрепите изображение.

Новые пакеты SkiaSharp и SkiaSharp.NativeAssets.Linux.NoDependencies уже добавлены. Ручная установка не нужна. Применена миграция ProductConcurrency. После остановки предыдущего экземпляра достаточно запустить проект заново.


## Этап 4: корзина

Все маршруты требуют входа. Корзина хранится в PostgreSQL отдельно для каждого пользователя и сохраняется после выхода и повторного входа.

- GET /api/cart — позиции, актуальные цены, общая сумма, сумма доступных позиций, предупреждения.
- PUT /api/cart/items/{productId} с JSON { "quantity": 2 } — добавить товар или установить точное количество от 1 до 10000. Повторение запроса не увеличивает количество.
- DELETE /api/cart/items/{productId} — удалить позицию, в том числе снятый с публикации товар. Повторное удаление допустимо.
- DELETE /api/cart — очистить собственную корзину.

Только опубликованные товары с достаточным остатком можно добавлять или менять по количеству. Для скрытого или отсутствующего товара возвращается 404, для недостаточного остатка — 409, для неверного количества — 400. Чужая корзина недоступна: идентификатор владельца берется из авторизованной сессии.

Каждая позиция содержит price (актуальную цену), priceAtAddition (цену при добавлении), priceChanged, quantity, lineTotal, stock, isAvailable и unavailableReason. Если товар закончился, снят с публикации или остаток меньше количества, позиция сохраняется с предупреждением, чтобы покупатель мог удалить ее или скорректировать количество.

Total — сумма всех позиций по актуальным ценам. AvailableTotal — сумма полностью доступных позиций. CanCheckout=false для пустой корзины или при наличии недоступной позиции. HasPriceChanges сообщает об изменениях цен; эта информация должна быть показана покупателю при оформлении. Цена при первоначальном добавлении не меняется при корректировке количества.

Добавление в корзину не резервирует товар и не уменьшает остаток. Окончательная проверка цен, статуса и остатков в транзакции реализована в пункте 4.5. Новые NuGet-пакеты не требуются. Миграция AddCart применена к локальному PostgreSQL. Перезапустите приложение, чтобы использовать новые маршруты.


## Этап 5: оформление заказов

POST /api/orders/checkout принимает requestId (новый GUID для нового оформления), recipientName, phone, deliveryAddress и items. Каждая позиция содержит productId, quantity, unitPrice (рубли) и version из GET /api/cart. Передайте все позиции корзины. Версия здесь относится к позиции корзины, а не к товару.

Покупатель должен сначала увидеть актуальную корзину и подтвердить цены и состав. При отличии переданных цен, количества, версии позиции, состава корзины, публикации или остатка сервер возвращает 409, не создает заказы и не меняет остатки. Обновите корзину, покажите изменения покупателю и отправьте новое оформление с новым requestId после подтверждения.

При успешном оформлении ответ 201 содержит отдельный заказ для каждого продавца. Записи заказов, снимки названий и цен товаров, уменьшение остатков и удаление оформленных позиций корзины сохраняются одной транзакцией. Для покупок используется уровень Serializable и контроль версии товара. Конкурирующие изменения приводят к ответу 409, а не к продаже сверх остатка.

Повтор точно такого же успешного запроса с прежним requestId возвращает 200 и те же заказы, даже если корзина уже очищена. Повтор с тем же requestId и другим содержимым запрещен. При сетевой ошибке или конфликте одновременных запросов сначала повторите прежний запрос с прежним requestId: это позволяет выяснить, было ли оформление завершено, без создания повторного заказа.

### Просмотр и статусы

- GET /api/orders — история покупателя, параметры page и pageSize.
- GET /api/orders/{id} — карточка заказа покупателя.
- POST /api/orders/{id}/cancel — отмена покупателем.
- GET /api/seller/orders — полученные заказы продавца.
- GET /api/seller/orders/{id} — карточка заказа продавца.
- POST /api/seller/orders/{id}/status с JSON { "status": "Confirmed" }, "Completed" или "Cancelled" — изменение статуса продавцом.

Переходы: New → Confirmed → Completed. Отмена возможна из New и Confirmed. После Completed и Cancelled новые переходы запрещены. Повтор уже установленного статуса допустим. При отмене остатки восстанавливаются в той же транзакции один раз, в том числе если товар снят с публикации; повторная отмена повторно остатки не увеличивает. Товар не публикуется автоматически.

Покупатель видит только свои заказы, продавец — только заказы своих товаров. Контактные данные доступны только участникам соответствующего заказа. Изменение названия, цены или публикации товара не меняет снимок товара в заказе. Онлайн-оплата и службы доставки пока не подключены.

Миграция AddOrders применяется к PostgreSQL. Новые пакеты не требуются. После обновления перезапустите приложение.

## Этап 6: личные кабинеты

После запуска откройте https://localhost:7153/ (или HTTPS-адрес из окна запуска). На стартовой странице открыт каталог. Для входа и регистрации используйте кнопку «Войти», для перехода в кабинет после входа — «Кабинет». В кабинете:

- Мой профиль: имя, электронная почта, редактирование имени, телефона и адреса. Email отображается без возможности изменения.
- Мои покупки: история с постраничным просмотром, состав, цены, контакты и статус заказа; отмена доступного для отмены заказа.
- Мои товары: постраничный список, создание черновика, редактирование, загрузка и удаление фотографий, публикация и снятие с публикации.
- Полученные заказы: постраничный список, детали, подтверждение, завершение и отмена.

Все страницы адаптированы для телефона. При ошибке данные формы остаются на экране. Устаревшая версия товара или профиля возвращает конфликт, требующий обновления данных. Контактные данные профиля не меняют уже оформленные заказы.

Дополнительный API: GET /api/profile и PUT /api/profile. При сохранении передайте displayName, phone (необязательно), deliveryAddress (необязательно) и version из GET. Пользователь может изменять только свой профиль.

Интерфейс размещен в wwwroot и обслуживается самим ASP.NET Core. Node.js, npm и отдельный сервер интерфейса для запуска не нужны. Миграция ProfileDeliveryAddress уже применена к локальной базе.

### Изменение запросов API

Для POST, PUT, PATCH и DELETE требуется заголовок X-NeAvito-Request: 1. Браузерный интерфейс добавляет его автоматически; примеры NeAvito.http обновлены. Добавьте этот заголовок и в запросы Postman, включая вход и загрузку фотографий. Запрос без заголовка возвращает 403. CORS не включен: браузер не разрешает сторонним сайтам отправлять изменяющие запросы с этим заголовком. GET-запросам заголовок не требуется.

Проверено 38 серверных тестов, включая PostgreSQL, и браузерный сценарий с тестовыми ответами API: вход, сохранение профиля, создание и публикация товара, смена статусов заказа, выход. Проверены макеты 1440 и 390 пикселей. Браузерная проверка не создает демонстрационные аккаунты и товары в пользовательской базе.


## Этап 7: публичный каталог и карточка товара

Откройте https://localhost:7153/ — каталог доступен без регистрации. Ссылка #catalog возвращает в каталог, #item?id=GUID открывает карточку товара. Вход доступен по #login, кабинет — по #profile.

- Поиск по названию, выбор категории, нижняя и верхняя границы цены, четыре варианта сортировки.
- По 12 товаров на странице. Фильтры сохраняются в URL, при переходах между страницами и возврате из карточки.
- Карточка показывает фотографии с переключением, описание, цену, наличие и имя продавца.
- Кнопка «В корзину» работает в выдаче и карточке. Гость сначала входит и возвращается к выбранному товару, после чего подтверждает добавление кнопкой.
- Если товар уже есть в корзине, отображается его количество; повторное открытие страницы его не меняет.
- Товары без остатка нельзя добавить. API повторно проверяет доступность при добавлении.
- Предусмотрены пустая выдача, ошибки загрузки, повторная попытка и сброс фильтров.
- Проверены широкий и мобильный экраны.

Дополнительных пакетов и миграций нет. После перезапуска приложения обновите страницу браузера; при старом интерфейсе используйте Ctrl+F5.

Проверки этапа: 38 серверных тестов; браузерные сценарии каталога и ранее созданных кабинетов с тестовыми ответами API. Браузерная проверка включала фильтры, страницы результатов, фотографии, возврат после входа, добавление, сохранение количества, недоступный товар, пустую выдачу, ошибку загрузки и отсутствие горизонтального переполнения на ширине 390 пикселей.
