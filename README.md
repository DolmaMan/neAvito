# NeAvito — доска объявлений

P0–P2 реализованы. Посетитель ищет вещь, открывает карточку, входит и нажимает «Показать телефон». Стороны договариваются напрямую. Сайт не принимает оплату, не оформляет доставку и не резервирует вещи.

Автор сохраняет частичные черновики, добавляет до 10 фото, выбирает категорию, город, состояние и цену (0 ₽ — бесплатно). Для публикации нужны заполненные поля, фото, телефон и отдельное согласие на его показ. Изменение номера требует нового согласия; его отзыв снимает объявление. Доступны снятие, продажа, возврат проданного в снятые и архив. Конфликт правок в двух вкладках возвращает 409.

Вход требует подтверждения почты. Реализованы восстановление и смена пароля, выход со всех устройств, защищённые сессии и глазок пароля. Профиль приватный: его изменения не меняют телефон объявления.

Каталог ищет по заголовку и описанию, сочетает фильтры категории, города, состояния и цены, сортирует по дате и цене со стабильной пагинацией. Телефон выдаётся отдельным запросом с no-store только вошедшему пользователю. Лимиты одного процесса: 10 запросов на аккаунт и 30 на IP за 15 минут, затем 429 с Retry-After. Скрытые, снятые и проданные объявления, а также объявления заблокированного или неподтверждённого автора недоступны публично.

## Подготовка



.NET 10 уже установлен. Установите Docker Desktop для Windows с официального сайта https://docs.docker.com/desktop/setup/install/windows-install/ и запустите его. Используйте Linux containers / WSL 2. Если установщик потребует WSL, выполните в PowerShell администратора `wsl --install`, перезагрузите компьютер и повторно запустите Docker Desktop.

В терминале из корня проекта:

```powershell
Copy-Item .env.example .env
```

Откройте .env и замените пароль своим локальным паролем. Затем:

```powershell
docker compose up -d postgres
dotnet tool restore
dotnet user-secrets init --project NeAvito
dotnet user-secrets set "ConnectionStrings:Postgres" "Host=localhost;Port=15432;Database=neavito;Username=neavito;Password=ВАШ_ПАРОЛЬ" --project NeAvito
dotnet ef database update --project NeAvito
dotnet dev-certs https --trust
dotnet run --project NeAvito --launch-profile https
```

Пароль должен совпадать с .env. User Secrets предназначен только для локальной разработки. Не добавляйте пароль в appsettings или исходный код.
Повторное изменение POSTGRES_PASSWORD не меняет пароль уже созданной базы: для существующей базы изменяйте пароль средствами PostgreSQL.

В Visual Studio откройте NeAvito.slnx, выберите NeAvito запускаемым проектом и профиль https.

### Настройка почты

В Development письма сохраняются в `NeAvito/App_Data/mail` как файлы `.eml`. Откройте последнее письмо в почтовой программе и перейдите по ссылке. При смене порта задайте `AccountEmail:PublicOrigin` с новым HTTPS-адресом.

Для стенда настройте переменные окружения:

| Переменная | Значение |
|---|---|
| `AccountEmail__PublicOrigin` | Внешний HTTPS-адрес сайта без пути |
| `AccountEmail__From` | Адрес отправителя, разрешённый SMTP-сервером |
| `AccountEmail__Host` | Хост SMTP с поддержкой STARTTLS |
| `AccountEmail__Port` | Порт SMTP, по умолчанию 587 |
| `AccountEmail__UserName`, `AccountEmail__Password` | Учётные данные SMTP, если сервер их требует |
| `DataProtection__KeysPath` | Путь к постоянному каталогу ключей с ограниченным доступом |

Публичная среда требует настроенный SMTP. Задайте `DataProtection__KeysPath` на защищённом постоянном томе для сохранения ключей ASP.NET Core Data Protection между выпусками. Дайте доступ к каталогу только процессу приложения. Реплики одного стенда должны использовать общий каталог ключей. За обратным прокси настройте доверенные forwarded headers, чтобы лимиты запросов применялись к IP посетителей.

Перед запуском обновлённой версии примените миграцию командой `dotnet ef database update --project NeAvito`. После обновления пользователи входят заново. Существующие аккаунты с неподтверждённой почтой сохраняются. На экране входа их владельцы запрашивают письмо подтверждения для своего адреса. Ссылки на подтверждение и сброс действуют один час.

## Проверка

Откройте NeAvito/NeAvito.http, замените базовый URL на HTTPS-адрес из окна запуска.
Последовательно выполните регистрацию, подтверждение по ссылке, вход, получение профиля и выход. Затем запросите восстановление и проверьте вход с новым паролем. HTTP-клиент должен сохранять cookie между запросами.
OpenAPI доступен в Development по /openapi/v1.json; графический Swagger UI пока не подключен.

```powershell
dotnet test NeAvito.slnx
```

Интеграционные тесты используют временную SQLite: проверяют HTTP-сценарии, но не заменяют проверку миграций и работы с PostgreSQL.


## Переход со старого каталога

Миграция `20261109172437_PublicListingsCutover` сохраняет ID, авторов, цены, описания и фотографии старых товаров. Черновик остаётся черновиком; прочие товары становятся снятыми объявлениями с пояснением в кабинете. Город, состояние и согласие заполняет автор. Профильные и заказные контакты не переносятся. Остаток не определяет статус «Продано».

Перед обновлением остановите старое приложение, сохраните резервную копию БД и фото. Миграция останавливается при New/Confirmed заказах или конфликте ID; сначала согласуйте завершение заказов/разрешите конфликт, затем повторите обновление. Перенос атомарный, повтор `database update` не дублирует записи.

Для вошедшего пользователя корзина, прежнее управление товарами и изменение заказов отвечают 410; защищённые маршруты для гостя сохраняют 401. История заказов доступна только участникам. Старые ссылки на публичные карточки и фото перенаправляются на новые API; `#products` и `#product?id=…` ведут в кабинет объявлений. БД запрещает INSERT/UPDATE/DELETE/TRUNCATE старых торговых таблиц, в том числе из старой версии приложения.

Автоматический Down намеренно запрещён: нельзя терять новые объявления и включать торговые записи при откате. Для восстановления поднимайте проверенную копию в отдельной БД; исправляйте приложение с сохранением ограничений записи. Удаление исторических таблиц — отдельный будущий этап после определения срока хранения.

## Повторяемая проверка

Используйте PowerShell 7 (`pwsh`), Docker Compose и PostgreSQL из локальной конфигурации:

```powershell
$env:NEAVITO_TEST_POSTGRES = '1'
dotnet test NeAvito.slnx
pwsh -File scripts/Verify-P0.ps1 -SkipRestore
```

Скрипт создаёт отдельные базы, проверяет миграции и восстановление копии, сохраняет result.json. Для браузерных сценариев запустите `scripts/Start-P0Server.ps1 -ReportPath <result.json>`, затем Node/Playwright со установленным Edge:

```powershell
node scripts/verify-auth-browser.cjs <result.json>
node scripts/verify-listings-browser.cjs <result.json>
node scripts/verify-catalog-browser.cjs <result.json>
```

Остановив тестовый сервер, выполните `scripts/Clear-P0Databases.ps1 -ReportPath <result.json>`. Результаты, снимки экрана и резервная копия сохраняются в закрытом от Git `App_Data`. Не публикуйте дампы и локальные письма.

Исторические тесты корзины и заказов запускаются только с `LegacyCommerce:Enabled=true` в среде `Testing`, на отдельных тестовых схемах без миграционных запретов. Этот флаг не включает старые операции в Development/Production. P2-тесты отдельно проверяют актуальный режим, приватность истории и запреты БД.

Следующий этап P3: роли модератора, жалобы, причины и аудит блокировок. `IsBlocked` уже закрывает вход, действующие сессии и публичные объявления, но интерфейса назначения блокировки пока нет. P4 — CI, контейнер приложения, Caddy/Let's Encrypt, SMTP и публичный стенд. P5 — Kafka/Outbox, Redis, выделение сервисов и Kubernetes. Чат, рекомендации и платежи не входят в текущий этап.
