# Учебный стенд с настоящими письмами

Нужны Docker Desktop (Linux containers), .NET 10 SDK, PowerShell 7 и интернет. Сайт работает на вашем ПК; письма отправляются через указанный вами SMTP-сервис.

## Однократная настройка

Из корня проекта запустите:

```powershell
pwsh -File scripts/Start-Demo.ps1
```

Если настройки ещё не созданы, скрипт создаст `NeAvito/App_Data/demo/demo.settings.json` и остановится с просьбой заполнить его. Откройте именно этот файл. `demo.settings.example.json` в корне — только пустой шаблон, не записывайте туда свои секреты.

| Поле | Что указать |
|---|---|
| AccountEmail.From | Полный адрес отправителя, разрешённый вашим SMTP-сервисом |
| AccountEmail.Host | SMTP-хост из настроек вашего почтового сервиса |
| AccountEmail.Port | Порт с STARTTLS, обычно 587 |
| AccountEmail.UserName | SMTP-логин, обычно полный адрес отправителя |
| AccountEmail.Password | Пароль приложения или SMTP-ключ, выданный вашим сервисом |
| Demo.ModeratorEmail | Ваш реальный адрес для аккаунта модератора |
| Demo.ModeratorPassword | Отдельный пароль входа на NeAvito: минимум 8 символов, строчные/прописные буквы, цифры и специальный символ |
| Demo.ModeratorDisplayName | Имя модератора на сайте |

Оставьте PublicOrigin равным `https://localhost:7353`, EnableSsl — `true`, PickupDirectory — пустой строкой. Текущий SMTP-клиент использует STARTTLS; порт 465 с неявным TLS не поддерживается. Если почтовый сервис требует разрешить SMTP или создать пароль приложения, сделайте это в его настройках. Обычный пароль от почты может не подходить.

SMTP-пароль и пароль модератора — разные поля для разных задач. Адрес отправителя и модератора могут совпадать. Файл JSON позволяет использовать `$`, `#` и пробелы в паролях без подстановок Compose; кавычки и обратный слеш нужно экранировать по правилам JSON. Файл хранится в игнорируемом Git каталоге App_Data и не включается в Docker-образ.

Повторите ту же команду запуска. Скрипт соберёт контейнер, применит миграции, создаст два демонстрационных аккаунта и вашего модератора, отправит ему письмо подтверждения. Windows может запросить доверие локальному HTTPS-сертификату.

## Вход и показ

Сайт: https://localhost:7353

- `seller@demo.test` и `buyer@demo.test` — готовые подтверждённые аккаунты для показа основного интерфейса. Начальный пароль — в `NeAvito/App_Data/demo/ACCOUNTS.txt`. Письма при их создании не отправляются.
- Модератор — ваш адрес из настроек и отдельный указанный пароль. Откройте реальный ящик на этом ПК, перейдите по ссылке и нажмите «Подтвердить почту». Затем войдите: появится «Модерация».
- Проверяющий открывает сайт, регистрируется со своим настоящим адресом и придумывает пароль. Письмо приходит в его обычный ящик; он открывает его на этом же ПК, переходит по ссылке и подтверждает адрес. До подтверждения войти нельзя.

Ссылки ведут на localhost. Если открыть письмо на телефоне или другом компьютере, ссылка не откроет этот стенд — на демонстрации открывайте почту на ПК со стендом. Для отдельного пользователя удобно приватное окно браузера. Письма могут попасть в спам; проверьте доставку со своей почтой заранее. Ссылка действует час, повторную можно запросить на экране входа. Восстановление пароля тоже отправляет настоящее письмо.

## Обновление прежнего демо

База, фото и история сохраняются. Общий `moderator@demo.test` лишается роли модератора; его прежние сессии отзываются. Старые тестовые пользователи не удаляются, но письма им при запуске больше не отправляются. Mailpit исключён из нового Compose и не используется приложением. Если старый контейнер Mailpit остался запущен, его можно остановить отдельно; прежние письма и том автоматически не удаляются.

Настроенному реальному адресу назначается Moderator, но подтверждение почты не обходится. При существующем аккаунте пароль не перезаписывается. Для смены пароля используйте восстановление/профиль. Изменение ModeratorPassword в JSON задаёт пароль только при первом создании аккаунта. Если поменять ModeratorEmail, новый адрес получит роль; ранее назначенные личные модераторы автоматически не лишаются прав. Для отзыва используйте операторскую команду из README.

## Запуск и остановка

После успешного запуска скрипт завершается и возвращает приглашение PowerShell. Это нормально: сайт и база продолжают работать в Docker в фоне. Окно PowerShell можно закрыть; Docker Desktop должен оставаться запущенным. Во время повторного запуска сообщение об остановке прежнего контейнера ожидаемо: скрипт останавливает приложение перед миграциями, затем запускает его снова.

```powershell
# Обычный запуск / обновление кода
pwsh -File scripts/Start-Demo.ps1
# Повторный запуск без пересборки (только после первой сборки новой версии)
pwsh -File scripts/Start-Demo.ps1 -NoBuild
# Остановка с сохранением данных
pwsh -File scripts/Start-Demo.ps1 -Action Stop
# Состояние
pwsh -File scripts/Start-Demo.ps1 -Action Status
```

При неподтверждённом модераторе повторный запуск отправляет новое письмо. Если SMTP вернул ошибку, настройка останавливается; исправьте параметры и повторите запуск. Созданный аккаунт сохраняется. Принятие письма SMTP-сервером не гарантирует попадание во входящие — окончательная проверка выполняется в реальном ящике.

## База и диагностика

База для IDE: host `localhost`, port `25432`, database/user `neavito_demo`. Пароль находится в `DEMO_DB_PASSWORD` файла `NeAvito/App_Data/demo/demo.env`. Подключение приложения автоматическое. Основная база neavito:15432 и User Secrets не меняются. Не удаляйте demo.env и Docker volumes, если нужны существующие данные.

```powershell
docker compose --env-file NeAvito/App_Data/demo/demo.env -f compose.demo.yaml logs --tail 100 app
pwsh -File scripts/Verify-Demo.ps1
# После подтверждения вашей почты; использует начальный пароль из настроек
pwsh -File scripts/Verify-Demo.ps1 -IncludeModerator
```

Проверочный скрипт не отправляет внешних писем и не регистрирует вымышленные адреса. Он проверяет входы, права и каталог. Доставку проверяйте регистрацией своего адреса вручную. До ввода SMTP-параметров внешняя доставка не может быть проверена.
